# Security and host responsibilities

The default schema has no raw HTML block. Paragraph content consists of text and typed inline marks. Default DOM renderers create text nodes; React renderers use escaped content. A string containing `<script>` is displayed as text. Unsafe URL protocols, credentials, malformed inputs, non-finite chart data, and invalid schema versions reject before any operation commits. Only HTTP/HTTPS hyperlinks are supported; embeds require HTTPS.

SuperChart embed descriptors do not automatically load an iframe. Hosts explicitly enable embeds and supply exact allowed HTTPS origins. Default iframe rendering uses a sandbox, no `allow-same-origin`, lazy loading, and no-referrer. Hosts must trust those origins and their chosen sandbox behavior. Configured custom block/chart renderers are trusted application code and can bypass default rendering safety; audit them separately. The core does not fetch URLs, so URL validation is not an SSRF policy. A host adding URL fetching must enforce its own network restrictions.

The actor in a transaction is provenance supplied by a caller, not an authentication credential. Never expose the HTTP/MCP adapters to untrusted clients without host authentication, authorization, request budgets, CSRF/origin policy where appropriate, and revision-guarded durable writes. Error responses are data, not instructions to weaken guards. A stale agent proposal must be re-read and reviewed; never retry by stripping expected versions.

The local CLI operates only on caller-selected report JSON files. It does not resolve remote URLs, invoke provider SDKs, call trading APIs, or persist session undo history. It takes an exclusive `.lock` file before reading and applying a transaction, then atomically replaces the document. Other writers must participate in that lock protocol. A stale lock fails safely and is left for explicit host recovery. Persistent applications must coordinate external writers and durable compare-and-swap updates separately.

Document size limits and bounded in-memory history help keep the vertical slice predictable. For production, define memory quotas, request timeouts, audit retention, durable idempotency semantics, and isolation for expensive custom chart rendering. This repo does not claim real-time collaboration, policy enforcement for trading, or a complete hosted service.
